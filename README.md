## 🧭 Methodology

Every engagement follows a structured, repeatable process:

```mermaid
flowchart LR
    A[🕵️ Recon & OSINT] --> B[🌐 Scanning & Enumeration]
    B --> C[🔍 Vulnerability Analysis]
    C --> D[⚔️ Controlled Exploitation]
    D --> E[📝 Reporting]
    E --> F[🛡 Remediation Advice]
    F -.retest.-> C
```

| Phase | What happens | Typical tools |
|:------|:-------------|:--------------|
| **1. Recon & OSINT** | Map the public footprint, domains, emails, and exposed information | theHarvester, Amass, SpiderFoot, Sherlock |
| **2. Scanning** | Discover hosts, ports, services, and technologies | Nmap, Masscan, Nikto |
| **3. Analysis** | Identify and prioritize weaknesses | Burp Suite, OWASP ZAP, Searchsploit |
| **4. Exploitation** | Safely validate impact within scope | Metasploit, custom scripts |
| **5. Reporting** | Clear findings, risk ratings, and proof of concept | Markdown / PDF reports |
| **6. Remediation** | Practical fixes and retesting guidance | Hardening recommendations |

## 📓 Recon Cheat Sheet

> ⚠️ Use only on systems you own or have written permission to test.

<details>
<summary><b>🌐 Network scanning (Nmap)</b></summary>

```bash
# Fast top-ports scan
nmap -T4 --top-ports 1000 <target>

# Service + version detection with default scripts
nmap -sV -sC -oA scan_results <target>

# Full TCP port sweep
nmap -p- --min-rate 1000 <target>
```

</details>

<details>
<summary><b>🔎 Subdomain & OSINT recon</b></summary>

```bash
# Passive subdomain enumeration
amass enum -passive -d example.com

# Emails and hosts from public sources
theHarvester -d example.com -b all

# Username lookup across social platforms
sherlock <username>
```

</details>

<details>
<summary><b>🕸 Web checks</b></summary>

```bash
# Quick web server misconfiguration scan
nikto -h https://example.com

# Look up known exploits for a discovered service
searchsploit "apache 2.4"
```

</details>

<details>
<summary><b>📝 Findings report template</b></summary>

```markdown
## Finding: <Title>
- **Severity:** Critical / High / Medium / Low / Info
- **Affected asset:** <URL / host>
- **Description:** What the issue is and why it matters
- **Steps to reproduce:** 1... 2... 3...
- **Impact:** What an attacker could achieve
- **Remediation:** Specific fix and references (OWASP / CWE)
```

</details>

### 🚩 Mini CTF: Can You Solve It?

Three quick levels. Decode each message to reach the next. The final one is a flag.

<details>
<summary><b>🟢 Level 1</b></summary>

```text
TmljZSBvbmUhIExldmVsIDIgdXNlcyBST1QxMy4=
```
_Hint: the "=" at the end is a clue. Try `echo '<text>' | base64 -d`._
</details>

<details>
<summary><b>🟡 Level 2</b></summary>

```text
Terng! Yriry 3 vf urk. Xrrc tbvat, unpxre.
```
_Hint: a Caesar cipher with a shift of 13._
</details>

<details>
<summary><b>🔴 Level 3</b></summary>

```text
56454e56495255537b77336c636f6d655f74305f7468335f6c34627d
```
_Hint: every two characters are one byte. Try `echo '<text>' | xxd -r -p`._
</details>

Solved it? [**Submit the flag via an issue**](https://github.com/Venvirus/Venvirus/issues/new?title=Flag%20submission&body=My%20flag%3A%20) and I may add you to the Hall of Fame.

## 🔒 Responsible Disclosure

If you find a security issue in any of my projects, please report it privately through
[GitHub Security Advisories](https://github.com/Venvirus/PhishFinder/security/advisories/new)
or through the appropriate private contact channel rather than opening a public issue. I aim to acknowledge reports promptly and credit researchers who help improve the security of these projects.
